# 事件报告增强设计

> 日期：2026-04-06
> 分支：dev/idc-deploy
> 状态：已确认，待实施

## 背景

当前事件报告功能存在以下不足：
1. **内容单调** — 仅展示 7 项指标（MTTD/MTTR/时长/严重性/服务/原因/重复），可视化形式单一
2. **AI 分析维度少** — 后端只让 LLM 生成 `most_frequent_reasons`（top 6），缺少趋势分析、根因定位、改进建议
3. **无模板选择** — 所有报告都是同一内容，用户无法按需选择分析类型
4. **无对话分析** — 用户无法与 AI 交互式探索事件数据
5. **展示粗糙** — 受影响服务仅用 Badge 标签、重复事件仅用列表，缺少图表和深度可视化

## 方案选型

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A：独立报告页面 | 新增 `/incidents/reports` 路由 | 空间充裕、可扩展 | 改动大、需新建路由和导航 |
| **B：增强弹窗 + 对话面板** | 在现有 Modal 基础上重构为左右面板 | 改动小、复用现有组件 | 空间有限（已够用） |

**选定方案 B**：增强现有弹窗，重构为左右面板布局。

## 整体架构

```
┌─────────────────────────────────────────────────────────┐
│  事件报告                                    [关闭]      │
├──────────┬──────────────────────────────────────────────┤
│ 报告模板  │  报告内容区                                   │
│ ──────── │                                              │
│ 综合报告  │  (根据左侧选择或对话结果渲染)                   │
│ 趋势分析  │                                              │
│ 根因分析  │                                              │
│ 深度分析  │                                              │
│ ──────── │                                              │
│ AI 对话   │                                              │
│  分析     │                                              │
└──────────┴──────────────────────────────────────────────┘
```

- **左侧导航**：4 个预定义模板 + 1 个 AI 对话分析入口
- **右侧内容区**：展示报告内容（预定义模板直出 / AI 对话后生成）
- 选择模板后直接异步生成报告，右侧展示加载状态和最终结果

## CopilotKit 复用

**复用 CopilotKit**（已集成 v1.54.1）：

1. 项目已有 CopilotKit 运行时（`/api/copilotkit/route.ts`）和 AI 模型配置
2. 事件详情页 `/incidents/[id]/chat/` 已有完整聊天实现可参考
3. `@copilotkit/react-ui` 的 `CopilotChat` 组件可直接内嵌

**实现方式**：
- 选择「AI 对话分析」tab 时，用 `<CopilotKit>` 包裹并挂载 `<CopilotChat>`
- 注册 `generate_report_from_chat` action，AI 将对话内容结构化为报告
- 对话的 system prompt 侧重引导用户分析事件数据并最终产出报告

## 报告模板定义

| 模板 | template_type | AI 分析维度 | 纯计算指标 |
|------|--------------|------------|-----------|
| **综合报告** | `comprehensive` | 全部（原因+趋势+根因+建议） | MTTD/MTTR/durations/severity/services/recurring |
| **趋势分析** | `trend` | 趋势识别、时间模式、频率变化 | 时间线分布、MTTD/MTTR 趋势 |
| **根因分析** | `root_cause` | 根因定位、关联分析、影响链路 | severity、services、recurring |
| **深度分析** | `deep` | 深度分析、风险评估、改进建议 | 全部计算指标 + 自定义指标 |

## 后端改动

### 扩展 Pydantic 模型

`keep/api/bl/incident_reports.py` 新增字段：

```python
class OpenAIReportPart(BaseModel):
    most_frequent_reasons: Optional[dict[str, list[str]]] = None
    # 新增
    trend_analysis: Optional[str] = None           # 趋势分析文本
    root_cause_analysis: Optional[str] = None      # 根因分析文本
    recommendations: Optional[list[str]] = None    # 改进建议
    risk_assessment: Optional[str] = None          # 风险评估
```

### 报告模型扩展

```python
class IncidentReport(BaseModel):
    # 现有字段全部保留...
    template_type: Optional[str] = None  # comprehensive/trend/root_cause/deep
```

### 多模板 Prompt 策略

根据 `template_type` 选择不同的 system prompt：

- **综合报告**：要求 AI 分析所有维度
- **趋势分析**：只要求趋势 + 时间模式分析
- **根因分析**：只要求根因定位 + 关联分析
- **深度分析**：要求全面分析 + 风险评估 + 改进建议

### 接口变更

`POST /incidents/report` 请求体增加 `template_type` 字段（默认 `comprehensive`）。

`GET /incidents/reports/{id}` 响应体增加 `template_type` 字段。

### DB 模型

`incident_report` 表增加 `template_type` VARCHAR 列。

## 数据流

### 预定义模板

```
用户选择模板 → POST /incidents/report {template_type}
                    ↓
            后端创建异步任务 (ARQ)
                    ↓
            前端轮询 GET /incidents/reports/{id}
                    ↓
            报告完成 → toast 通知 → 渲染报告
```

### AI 对话分析

```
用户选择 AI 对话 → CopilotChat 加载
                    ↓
            用户与 AI 对话分析事件数据
                    ↓
            AI 调用 generate_report_from_chat action
                    ↓
            对话内容结构化 → 生成报告 → 渲染
```

## 验收标准

1. 弹窗左侧可切换 4 种报告模板 + AI 对话分析
2. 预定义模板选择后异步生成，完成后自动展示
3. AI 对话分析可交互式分析事件数据，生成结构化报告
4. 报告展示包含：趋势分析、根因分析、改进建议、风险评估（按模板选择显示）
5. 受影响服务以条形图展示、重复事件以时间线展示
6. 生成完成后 toast 通知，可跳转报告历史
7. 所有新增 UI 文案均有中英文 i18n
