# Claude Code 项目配置最佳实践

> 基于 Claude Code 官方文档整理，记录 `.claude/` 目录结构、CLAUDE.md 用法、记忆系统等最佳实践。

## 一、`.claude/` 官方目录结构

```
your-project/
├── CLAUDE.md                      # 项目指令（团队共享，自动加载）
├── CLAUDE.local.md                # 个人偏好（不提交，手动加 .gitignore）
├── .mcp.json                      # 项目级 MCP 配置（团队共享）
│
└── .claude/
    ├── settings.json              # 团队权限/hooks 配置（提交 git）
    ├── settings.local.json        # 个人覆盖（自动 gitignore）
    │
    ├── rules/                     # 分主题规则文件
    │   ├── testing.md             # 无 paths → 始终加载
    │   ├── api-design.md          # 有 paths → 匹配文件时才加载
    │   └── frontend/
    │       └── react.md           # 支持子目录递归发现
    │
    ├── skills/                    # 可复用技能（/名称 调用）
    │   └── security-review/
    │       ├── SKILL.md           # 技能入口
    │       └── checklist.md       # 支撑文件
    │
    ├── commands/                  # 单文件命令（旧机制，推荐用 skills/）
    │   └── fix-issue.md           # /fix-issue <参数>
    │
    ├── agents/                    # 子代理定义
    │   └── code-reviewer.md       # 每个文件定义一个子代理
    │
    └── agent-memory/              # 子代理持久记忆（自动生成）
        └── <agent-name>/MEMORY.md
```

## 二、自动加载机制

每次对话启动时，Claude Code **自动加载**以下内容：

| 文件 | 加载时机 | 跟 git |
|------|---------|--------|
| `~/.claude/CLAUDE.md` | 全局，所有项目 | 否 |
| `CLAUDE.md` 或 `.claude/CLAUDE.md` | 项目级，**二选一** | 是 |
| `CLAUDE.local.md` | 项目级，追加加载（优先级更高） | 否 |
| `~/.claude/rules/*.md` | 全局规则 | 否 |
| `.claude/rules/*.md`（无 paths） | 项目规则，始终加载 | 是 |
| `~/.claude/projects/<path>/memory/MEMORY.md` | 自动记忆，前 200 行/25KB | 否 |

**按需加载**（延迟到读取相关文件时）：
- 子目录中的 `CLAUDE.md`
- `.claude/rules/` 中带 `paths:` 前置条件的规则

## 三、CLAUDE.md 最佳实践

### 3.1 放置位置

| 文件 | 用途 | 提交 |
|------|------|------|
| `CLAUDE.md`（根目录） | 项目约定，团队共享 | 是 |
| `.claude/CLAUDE.md` | 同上，保持根目录整洁时用 | 是 |
| `CLAUDE.local.md` | 个人偏好（本地路径、测试数据等） | 否（需手动 .gitignore） |

**注意：** `CLAUDE.md` 和 `.claude/CLAUDE.md` 是**二选一**，不要两个都放，避免重复。

### 3.2 行数控制

- **建议 200 行以内**，超长文件 Claude 遵循度下降
- 大项目用 `.claude/rules/` 拆分指令
- 用 `paths:` 条件加载减少不必要上下文消耗

### 3.3 内容结构建议

```markdown
# 项目名 项目约定

## 技术栈
## 本地开发
## 分支策略
## 工作流程
## 编译与重启
## 常见问题
```

## 四、`.claude/rules/` 规则文件

### 无条件加载（始终生效）
```markdown
# testing.md
- 所有测试使用 Vitest
- 覆盖率目标 80%
```

### 条件加载（仅匹配时生效）
```markdown
---
paths:
  - "src/api/**/*.ts"
  - "tests/**/*.test.ts"
---
# API 开发规则
- 所有端点必须用 Zod 校验输入
- 返回格式: { data: T } | { error: string }
```

### 支持的 glob 模式

| 模式 | 匹配 |
|------|------|
| `**/*.ts` | 所有 TypeScript 文件 |
| `src/**/*` | src/ 下所有文件 |
| `src/**/*.{ts,tsx}` | 支持 brace expansion |

## 五、settings.json 层级

### 优先级（从高到低）

1. **Managed settings**（企业 IT 部署，不可覆盖）
2. **CLI 命令行参数**
3. **`.claude/settings.local.json`**（个人项目级）
4. **`.claude/settings.json`**（团队项目级）
5. **`~/.claude/settings.json`**（个人全局级）

### 合并规则
- 数组设置（如 `permissions.allow`）：**拼接并去重**
- 标量设置（如 `model`）：**取最高优先级的值**

## 六、自动记忆系统

Claude Code 自动维护的记忆存储在：
```
~/.claude/projects/<project-path-hash>/memory/MEMORY.md
```

- **不跟 git**，机器本地
- 自动加载前 200 行或 25KB
- 支持主题文件（如 `debugging.md`），按需读取
- 换机器不会自动迁移

### 如果需要跨机器共享记忆

把记忆内容写进项目的 `CLAUDE.md` 或 `.claude/rules/`，这些跟 git 版本控制。

## 七、常用命令

| 命令 | 作用 |
|------|------|
| `/init` | 自动生成初始 CLAUDE.md |
| `/memory` | 查看当前会话加载了哪些记忆文件 |
| `/context` | 查看各部分 token 占用情况 |

## 八、本项目的配置

本项目（Keep）使用：
- `CLAUDE.md`（根目录）— 项目约定 + 记忆，合并为单一文件
- `.claude/settings.json` — 项目级设置
- `.claude/settings.local.json` — 个人覆盖
- `.claude/rules/` — 按需添加分主题规则
- `~/.claude/projects/.../memory/MEMORY.md` — 指向项目 CLAUDE.md，不重复维护
