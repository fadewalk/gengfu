# 认证模式功能限制调整

> 日期: 2026-04-05
> 分支: dev/idc-deploy

## 背景

Keep 前端对不同认证模式（AUTH_TYPE）有功能限制。原设计中部分限制过于严格，导致 LDAP 模式下缺少关键功能。

## 认证类型

| AuthType | 说明 |
|----------|------|
| `NOAUTH` | 无认证，单用户模式 |
| `DB` | 本地数据库认证 |
| `LDAP` | LDAP/AD 认证 |
| `KEYCLOAK` | Keycloak SSO |
| `AUTH0` | Auth0 SSO |
| `AZUREAD` | Azure AD |
| `OKTA` | Okta SSO |
| `ONELOGIN` | OneLogin SSO |
| `OAUTH2PROXY` | OAuth2 代理 |

## 修改内容

### 文件: `keep-ui/app/(keep)/settings/settings.client.tsx`

| 功能变量 | 修改前 | 修改后 | 原因 |
|----------|--------|--------|------|
| `customRolesAllowed` | `=== KEYCLOAK` | `!== NOAUTH` | 角色存 Keep 自己数据库，跟认证方式无关 |
| `permissionsAllowed` | `=== KEYCLOAK` | `!== NOAUTH` | 权限管理是数据层操作，后端无认证类型限制 |
| SSO Tab | 不允许时 disabled 显示 | `className="hidden"` 隐藏 | 非 Keycloak 不需要 SSO 配置页面，隐藏更干净 |
| SSO TabPanel | 条件渲染 | `className="hidden"` 隐藏 | 保持 Tab index 对齐 |

### 文件: `keep-ui/app/(keep)/settings/auth/users-settings.tsx`

| 修改 | 说明 |
|------|------|
| 用户创建按钮 | `disabled={!userCreationAllowed}` → 条件渲染隐藏 | Azure AD/NOAUTH 不支持创建用户，直接不显示按钮 |

## 保留不动的限制

| 限制 | 范围 | 原因 |
|------|------|------|
| 用户管理整体 | NOAUTH 排除 | 无认证没有用户概念 |
| 用户创建 | NOAUTH + AZUREAD 排除 | Azure AD 用户从 Entra ID 同步 |
| SSO Tab | 仅 Keycloak | SSO 登录配置是 Keycloak 专属功能 |
| 密码字段 | 仅 DB + Keycloak | LDAP/AzureAD 密码在外部 IdP 管理 |

## 其他页面检查结论

对 alerts、incidents、workflows、providers、explorer、topology 等业务页面的搜索确认：**业务页面没有任何认证类型限制代码**，所有功能开关集中在设置页面和认证框架层。
