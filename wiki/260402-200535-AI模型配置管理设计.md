# AI 模型配置管理 — 数据库驱动多模型/多场景支持

> 提交: `7a8e5a62` | 分支: `feature/group-isolation` | 日期: 2026-04-02

## 背景

Keep 原先的 AI 模型配置依赖环境变量（`OPENAI_API_KEY`, `OPENAI_MODEL_NAME`, `OPENAI_BASE_URL`），存在以下问题：
- 只支持单一模型，无法按场景（告警聚类、事件报告、Copilot 等）配置不同模型
- 修改模型需要重启服务
- 无法在 UI 上管理模型配置

## 方案

### 数据库模型

新增 `ai_model_config` 表：

```python
class AiModelConfig(Base):
    __tablename__ = "ai_model_config"
    id = Column(String, primary_key=True)
    tenant_id = Column(String, nullable=False, index=True)
    name = Column(String)           # 配置名称，如 "智谱 GLM-5"
    provider = Column(String)       # 提供商标识，如 "zhipu"
    model_id = Column(String)       # 模型 ID，如 "glm-5"
    api_key = Column(String)        # API Key（加密存储）
    base_url = Column(String)       # API 端点
    scenario = Column(String)       # 使用场景：alert_correlation / incident_report / copilot
    is_default = Column(Boolean)    # 是否为该场景默认模型
    extra_params = Column(Text)     # 额外参数 JSON
    created_at / updated_at
```

### API 路由

| 路由 | 方法 | 说明 |
|------|------|------|
| `/ai/models` | GET | 列出所有模型配置 |
| `/ai/models` | POST | 创建模型配置 |
| `/ai/models/{id}` | PUT | 更新模型配置 |
| `/ai/models/{id}` | DELETE | 删除模型配置 |
| `/ai/scenarios` | GET | 获取场景列表及默认模型映射 |

### 业务逻辑层

`ai_model_service.py` 提供：
- `get_model_for_scenario(tenant_id, scenario)` — 按场景获取模型配置，回退到环境变量
- `list_models(tenant_id)` / `create_model()` / `update_model()` / `delete_model()`
- 支持场景默认模型切换

### 消费方改造

- `ai_suggestion_bl.py` — 告警聚类调用 `get_model_for_scenario("alert_correlation")`
- `incident_reports.py` — 事件报告调用 `get_model_for_scenario("incident_report")`
- 前端 AI 设置页面重构，支持模型 CRUD 和场景分配

### 前端改造

`ai-settings.tsx` 重写：
- 模型管理面板：添加/编辑/删除模型配置
- 场景映射面板：为每个场景选择默认模型
- 表单字段：名称、Provider、模型 ID、API Key、Base URL、额外参数

## 环境变量兼容

当数据库中没有配置时，自动回退到环境变量：
```
OPENAI_API_KEY
OPENAI_BASE_URL
OPENAI_MODEL_NAME
```
