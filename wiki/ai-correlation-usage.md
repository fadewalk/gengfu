# AI 关联引擎 — 使用指南

> 适用于 Keep 开源版自托管部署

## 概述

AI 关联引擎（AI Correlation Engine）是 Keep 平台内置的告警智能化功能。它利用大语言模型（LLM）分析告警的语义关联性、时间接近性、受影响系统和依赖关系，将相关告警自动分组为事件（Incident），帮助你快速定位根因。

## 前提条件

### 1. 配置 LLM 服务

在 `docker-compose.yml` 或 `.env` 中设置以下环境变量：

```bash
# 必填：LLM API 密钥
OPENAI_API_KEY=your-api-key

# 可选：自定义 LLM 端点（支持任何 OpenAI 兼容 API）
OPENAI_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4

# 可选：指定模型名称
OPENAI_MODEL_NAME=glm-5
```

**已测试兼容的模型：**

| 模型 | 提供方 | 端点 |
|------|--------|------|
| GLM-5 / GLM-5.1 | 智谱 | `https://open.bigmodel.cn/api/coding/paas/v4` |
| Kimi-2.5 | 月之暗面 | `https://api.moonshot.cn/v1` |
| MiniMax-2.5 | MiniMax | `https://api.minimax.chat/v1` |
| GPT-4o | OpenAI | `https://api.openai.com/v1`（默认） |

> 提示：任何兼容 OpenAI Chat Completions API 的服务都可以使用。

### 2. 确保有告警数据

AI 关联引擎需要分析已有告警。请确保系统中已有通过 Provider 推送的告警数据。

## 操作步骤

### 一键关联

1. 点击页面右上角橙色按钮 **「立即关联」**
2. 系统获取最近 N 条未分配告警（N 由「每批最大告警数」配置决定）
3. 发送到 LLM 进行语义分析（约 30-60 秒）
4. 页面显示关联结果卡片：
   - **已分析**：本次处理的告警数量
   - **建议事件**：LLM 认为可以组成事件的分组数
   - **达标事件**：置信度 ≥ 阈值的分组数
   - **已创建**：实际创建的事件数（需开启「自动创建事件」）
5. 如果自动创建事件成功，页面顶部会弹出成功提示

### 调整算法配置

在 **LLM Alert Correlation** 卡片的配置区域，可以实时调整以下参数：

| 配置项 | 类型 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| 已启用 | 开关 | 开 | 开/关 | 关闭后「立即关联」按钮不可用 |
| 每批最大告警数 | 滑块 | 20 | 5-50 | 单次分析处理的告警上限。值越大 LLM 调用越贵，但关联准确度可能更高 |
| 置信度阈值 | 滑块 | 0.50 | 0.0-1.0 | LLM 给出的置信度低于此值的事件建议会被丢弃 |
| 自动创建事件 | 开关 | 开 | 开/关 | 关闭后仅存储建议，不自动创建事件 |
| 包含拓扑上下文 | 开关 | 关 | 开/关 | 开启后将服务拓扑关系作为额外上下文发送给 LLM |

> 提示：滑块类配置项有 1 秒防抖，调整后会自动保存。

### 查看执行日志

每个算法卡片底部显示最近 10 条执行日志，包含：
- 执行时间
- 处理的告警数
- 建议事件数
- 创建结果

## 工作原理

```
告警数据 ──→ Prompt 构建 ──→ LLM 分析 ──→ 结果归一化 ──→ 置信度过滤 ──→ 事件创建

                ↓ Prompt 包含：
                • 每条告警的名称、描述、严重度、来源、时间
                • 可选的服务拓扑关系
                • JSON Schema 输出约束
```

**关键设计**：

1. **模型无关**：通过 FIELD_MAP 兼容层自动归一化不同 LLM 返回的字段名差异
2. **容错解析**：LLM 可能返回告警名称（字符串）而非索引（数字），系统自动解析匹配
3. **置信度控制**：低置信度的建议自动丢弃，避免误报
4. **手动/自动**：可关闭自动创建事件，仅查看 AI 建议后人工审核

## 常见问题

### Q: 点击「立即关联」后长时间无响应？

LLM 调用通常需要 30-60 秒。如果超过 2 分钟无响应，检查：
- `OPENAI_API_KEY` 是否正确
- `OPENAI_BASE_URL` 是否可达（`curl $OPENAI_BASE_URL/models`）
- 后端日志：`docker compose logs keep-backend | grep correlate`

### Q: 关联结果为 0 条建议？

可能原因：
- 系统中没有未分配的告警（所有告警已归属事件）
- LLM 判断当前告警之间没有强关联
- 置信度阈值设置过高，尝试降低到 0.3

### Q: 建议事件多但已创建为 0？

检查「自动创建事件」开关是否开启。如果关闭，系统仅记录建议，不创建事件。

### Q: 想用国产模型，怎么配置？

```yaml
# docker-compose.yml 示例
environment:
  - OPENAI_API_KEY=your-zhipu-api-key
  - OPENAI_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4
  - OPENAI_MODEL_NAME=glm-5
```

修改后重启后端：`docker compose restart keep-backend`

### Q: 如何关闭自动创建事件，改为手动审核？

将「自动创建事件」开关关闭。后续关联运行会记录建议但不会创建事件。你可以在执行日志中查看 LLM 的建议内容。
