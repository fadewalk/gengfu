## 一、需要商业授权（EE 企业版）的部分

### 1. 企业级身份认证（`keep/ee/identitymanager/`）

| 身份提供商 | 路径 | 说明 |
|-----------|------|------|
| **Auth0** | `keep/ee/identitymanager/identity_managers/auth0/` | 多租户 SaaS 认证 |
| **Azure AD** | `keep/ee/identitymanager/identity_managers/azuread/` | 单租户企业 AD |
| **Keycloak** | `keep/ee/identitymanager/identity_managers/keycloak/` | 完整 RBAC/ABAC + SSO |

开源部分仅支持：NOAUTH、DB、LDAP、OAuth2 Proxy、Okta、OneLogin。

### 2. AI 驱动的事件智能（`ee/experimental/`）

通过 `keep/api/utils/import_ee.py` 动态加载，需要同时满足 `EE_ENABLED=true` + Redis 可用：

- **事件摘要自动生成**（`process_summary_generation`）
- **事件名称自动生成**（`process_name_generation`）
- **智能算法执行**（`process_algorithm`）

当 EE 关闭时，`ALGORITHM`、`SUMMARY_GENERATOR`、`NAME_GENERATOR` 均回退为 `NotImplemented`。

### 3. 授权控制机制

- 环境变量 `EE_ENABLED` 控制全局开关
- `TenantConfiguration` 数据库表支持按租户粒度开关
- PostHog 遥测上报 `ee_enabled` 状态
- **无 API 路由级别的守卫** — 所有 API 路由共享同一套认证，EE 功能通过动态 import 控制

### 4. 对 IDC 部署的影响

当前 IDC 部署使用 NOAUTH 模式，EE 目录虽有代码但未启用。若需要 Keycloak/Azure AD 认证或 AI 摘要功能，需要购买商业授权。

## 七、优先级建议（IDC 内网部署视角）

### 高优先级（影响用户体验）

1. **DateRangePicker 三个空函数** — 用户点击快退/前进/缩放无反馈
2. **Incident Activity 系统重构** — 核心功能技术债，开发者自己标注 "A MESS"
3. **服务端数据加载**（4 个 incidents 子页面）— 纯客户端加载影响性能
4. **告警分配审计** — `canAssign` 硬编码 `true`，无审计追踪

### 中优先级（功能完善度）

5. **RBAC 系统** — 当前过于简陋，仅支持基础角色
6. **工作流解析器多步骤支持** — 限制了工作流复杂度
7. **YAML 编辑器内联错误校验** — 用户编写工作流时缺少反馈
8. **CEL-to-SQL 翻译器** — 过滤表达式能力受限
9. **事件回放** — `NotImplementedError` 直接报错

### 低优先级（可延后）

10. **Coming Soon Providers**（Salesforce/Zendesk 等）— 按需实现
11. **移动端支持** — 仅占位页面
12. **Feature Flag 系统** — 当前无需求
13. **Noise Alerts 缓存** — 影响较小
14. **拓扑搜索类型修复** — 功能可用但类型不严谨
